# CLAUDE.md

Guidance for Claude Code when working in this directory (future repo `cc38324/MiYueCrestronDriver`).

## Purpose

Crestron 4-series driver for MiYue (米悦) background-music players over the player's **UPnP/SOAP**
interface (MiyueLibrary / MiyueQueue / MiyueAudioSource / MiyueSystem / MiyueSensor / MiyueGroup +
standard AVTransport / RenderingControl). It is the third integration of the same protocol, after the
Control4 driver (`cc38324/MiYueControl4Driver`, Lua) and the Home Assistant integration
(`cc38324/MiYueHaPlugin`, branch `upnp`, Python). **Where those two differ, follow the newer HA behaviour**
and note the difference (README "Firmware differences"). Code comments are English; user-facing status
strings are bilingual "中文 / English" — keep them that way.

The authoritative record of firmware behaviour is the C4 repo's `tests/fixtures/contract_verified.json`
(verified live on Android and Linux firmware) plus the HA repo's `docs/CONTRACT.md`. **Only use SOAP actions
and arguments that appear there** — `ContractTests` enforces it against the two firmware SCPD dumps.

`MiYue.Crestron.csproj` **compiles the core's sources in** (`<Compile Include="..\MiYue.Core\**\*.cs">`)
instead of referencing the netstandard2.0 DLL, so the `.clz` holds one self-contained `MiYue.Crestron.dll`
and no netstandard facades have to resolve on the processor. Anything added to `MiYue.Core` must therefore
compile for net472 / C# 7.3 (`LangVersion 7.3` in both projects) and must not reference Crestron types.

## Rules

- **Threading.** Every entry point from SIMPL+ only posts onto the `Strand` and returns — nothing may block
  the SIMPL+ thread. HTTP completions and timer ticks are re-posted onto the strand; all engine state is
  strand-only, so the engine has no locks. Use `Runtime.After(ms, action)` for timers (never raw
  `CTimer` in the core), `DeviceLink.Call` / `PlayerEngine.Call` for SOAP.
- **Requests** go through the per-device `RequestQueue` (max 2 in flight, like the C4 `Soap` FIFO) with a
  watchdog (timeout + 10 s). Never add a second path to the transport.
- **Polling never overlaps.** The next cycle is armed only when the current one finishes (or its 60 s
  watchdog fires); commands use `PollSoon(ms)`, which coalesces. A transport failure on GetTransportInfo
  ends the cycle; any other step failure keeps the previous value and continues. `Poll_cycles_never_overlap`
  guards this.
- **Offline.** 3 consecutive transport failures → offline → re-resolve with 5/15/30/60 s backoff; the
  probe tries the last good port first. A 404 from a hidden MediaRenderer is NOT a transport failure.
- **Outputs** are written in full by `Publish()`; `OutputCache` forwards only changes. `Refresh` resyncs.
- **Signal numbers** live in `Engine/Signals.cs` and as `#DEFINE_CONSTANT` in the `.usp` files. Change both
  together; `SignalContractTests` compares them and checks every `player.X(` / `RegisterDelegate` the
  `.usp` uses exists on the facade. After changing player I/O run `python macro/gen_umc.py`.
- `.usp` files must stay **pure ASCII** (the SIMPL+ editor expects ANSI) — tested.
- Scenes are **activate-only** (`ExecuteSensor`); no scene editing, no alarms (HA dropped them). No
  collect/uncollect (HA does not support it).

## Protocol notes (details: C4 contract_verified.json, HA docs/CONTRACT.md)

- Port starts at 49495 and drifts up to 49520 (pupnp FD leaks); `description.xml` gives control URLs.
- Headers: `Content-Type: text/xml; charset="utf-8"`, `SOAPACTION: "<serviceType>#<action>"`,
  `Connection: close` (pupnp drops POSTs on half-closed keep-alive connections).
- Unknown actions fault 501 (Android) / 401 (Linux). Only a UPnPError errorCode is a genuine fault.
- Queue indices are 0-based. `GetQueue.CurrentIndex < 0` = no queue index (-1 idle, ≤ -100 external owner:
  -100 radio, -101 DLNA, -102 AirPlay, -103 AUX, -104 SPDIF, -105 sync slave, -106 Bluetooth, -107.. TTS/voice).
  `RequestedCount 0` means "all" — the poller reads `GetQueue(cur, 1)`.
- Now playing: AVTransport `TrackMetaData` first, GetQueue item second; cleared when the queue is empty and
  nothing is PLAYING. Artist = `upnp:artist` falling back to `dc:creator` (Android).
- Skip (HA `_skip`): gated by songSrc (`SongSrc.CanSkip` / `Effective`); a slave only when CurrentIndex is
  -105. Try AVTransport Next/Previous; on a genuine fault only, SeekToTrack(fresh index ±1, no wrap) and only
  for queue sources. Never after a transport error (Next may have run).
- `SetVolume` must be an integer string (non-numeric = 0). `PlayTTS` must always carry Volume 1..100.
  TTS flips TransportState to PLAYING briefly — the poller ignores 2 cycles (`_ttsHold`).
- `SetInputOpen(Source, On="1"/"0")` is asynchronous on Android (tens of seconds): send once, let the poll
  pick it up. `SelectSource("Music")` closes external inputs but does not resume the queue.
- `ReplaceQueue(Items, StartingIndex≥0)` replaces and auto-plays; feed DIDL back verbatim. Collected radios
  with an empty `<res>` get the qingting URL (`FillRadioRes`); other direct-link sources (10, 21) without a
  URL are refused.
- Groups (HA group.py): read master GetGroupInfo → `SetGroupConfig(TargetUUID, GroupID, MasterIp,
  MulticastAddr, Role)` on the master FIRST, then each slave with the master's values → settle 900 ms →
  re-read. MasterIp = the master's own IPv4 (validated); never fabricate GroupID / MulticastAddr. Leave:
  `LeaveGroup()`; fewer than 2 left → LeaveGroup on every member (no cascade). Role None vetoes GroupID;
  a cluster of 1 is standalone. Group ops are serialized (queued, never dropped). A slave casts URLs to its
  leader (firmware answers 705 to an untagged SetAVTransportURI on a slave).

## Testing / building

```
cd crestron
dotnet test tests/MiYue.Core.Tests                               # offline, any OS
dotnet build src/MiYue.Crestron/MiYue.Crestron.csproj -c Release  # -> bin/Release/net472/MiYue.Crestron.clz
python macro/gen_umc.py                                          # regenerate the user macro
```

Tests use `Support/Rig` (inline strand, `ManualScheduler` virtual clock, `FakeNetwork` with simulated
`FakeMiyue` players that emulate the contract: port drift, faults, 404 renderer, group roles, holds for
stalled responses). New device behaviour gets a fixture-backed test; new SOAP calls must pass
`ContractTests`.

Unverified (no tooling here): the `.usp` files (never compiled by SIMPL+), the `.umc` (argument definition
missing), and the Crestron adapter on real hardware.
